# #013 AIカスタマーサービスエージェント（$1.3M, India）— スキップ

## サービスの中身
問い合わせの80%超をAIエージェントが自動解決する汎用カスタマーサポートSaaS。SEO・コンテンツ（技術ブログ600本超）によるPLG。B2Bサブスク＋従量。

| 項目 | 値 |
|---|---|
| TTM売上 / 利益 | $483.9k / $40k（**利益率8.3%**） |
| 先月 | $47.3k / $12k（25%） |
| 顧客数 / ARR | 101〜250 / $479k |
| 客単価 | 月$160〜395 |
| 年成長率 | **-26%** |
| チャーン | 1-3%（安定）← ただし下記参照 |
| 売却理由 | **Business challenges にチェック**（「技術は強いが販売が弱い」と正直に記載） |
| スタック | React / AWS / Python / OpenAI / Java / Flutter ほか多数（乱立気味） |
| 資金調達 | ブートストラップ＋借入＋エンジェル（友人家族から$240k） |
| 競合 | Ada.cx, Yellow.ai, Intercom, Zendesk（大手を正直に記載） |
| 価格 | $1.3M（31.3x profit / 2.6x rev） |
| 創業 / チーム | 不明 / 2-20人 |

## 検算で見つけた矛盾
- **チャーン1-3%なのに成長-26%**。顧客数は減っていないのに売上が縮む＝**従量課金の逆回転**（会話数ベースの収益が顧客あたりで縮小、NRR<100%）。チャーン欄は顧客数ベースであり、売上の健全性を保証しない — criteria に追加すべき新パターン
- 31.3x profit は論外の水準。2.6x revenue も縮小中の売上に対して過大
- 利益率8.3% — AI推論コストと人件費が粗利を食う構造（#004で見た「スケールがコストを食う」の実例）
- 先月×12 = $568k > ARR $479k — 直近に従量スパイクがあるが、単月では傾向を覆せない

## この事業の強み
100M会話の処理実績、月14,000のオーガニック流入、技術ブログ600本のSEO資産。技術は本物らしい。

## 差別化ポイント
消滅。Intercom Fin・Zendesk AIが同機能を標準搭載した時点で、独立系の汎用AIサポートは価格競争しか残らない。売主自身が「販売が弱い」と認めている。

## 判断
**スキップ**。基準1（成長マイナス）と基準3（Business challenges）で二重赤。

## 持ち帰った型
なし。ただしcriteria更新: **「チャーン低×成長マイナス」は従量課金の逆回転を疑う**（チャーン欄は顧客数ベース）。
